## 指摘

### 1. 移行後の時系列が既定のbackoff値でしか成立しない — 重大度: 低

**根拠:** 確定仕様`:96-105`、`feedian/store.py:907-909`、`feedian/vault.py:71-72`

**現象:** 確定仕様の「C. 移行」は、移行直後の行が「最後の失敗から30分以上経っていれば即座にdue」であり、「2回目の失敗まで60分以上空く」と述べる。しかしbackoffは`retry_base_minutes * 2**(consecutive_failures - 1)`を`retry_max_days`で打ち切った値である（`feedian/store.py:907-909`）。30分と60分は`retry_base_minutes`の既定値30に`consecutive_failures`が1と2を入れた結果であり、`retry_base_minutes`を120にしたVaultでは120分と240分になる。

**影響:** 既定以外の設定を使う読者が、仕様の記述する待機時間を自分のVaultの挙動と取り違える。

**限定条件（本文書で追記する）:** 仕様`:96-105`の「30分」「60分」は`retry_base_minutes = 30`（既定）における値である。一般には、移行直後の行は最後の失敗から`retry_base_minutes`分以上経過していればdueとなり、1回目と2回目の失敗の間隔は`retry_base_minutes * 2`分以上（いずれも`retry_max_days`で頭打ち）である。

**保証そのものは設定に依存しない。** 仕様が保証すると述べた2点のうち、**「一時的な障害1回では終端にならない」は`retry_base_minutes`の値によらず成立する。** これは`terminal_kind_failures`が2以上であることだけに依存し、backoffの長さとは無関係である。移行時リセットが防ごうとした事故は、どの設定でも防がれている。設定によって変わるのはもう一方、すなわち2回の失敗を隔てる実時間の長さだけである。
